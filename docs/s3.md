# S3 Configuration

IAM examples below use AWS ARN format. For non-AWS S3-compatible providers (B2, Wasabi, MinIO, R2), consult provider-specific IAM documentation.

## Supported Credential Modes

For each `remotes[]` entry, configure exactly one credential mode:

- `access_key_id` + `secret_access_key`: explicit static credentials. Common for non-AWS S3 providers.
- `aws_profile`: named profile from local AWS shared config/credentials files.
- `credential_source: default_chain`: AWS SDK default chain (for example env vars, shared config, instance profile, task role).

These modes only affect how the client authenticates. Bucket policy, IAM scope, versioning, and Object Lock guidance below still apply.

## Minimum IAM Permissions

### Backup Host (Write-Only)

The backup host only needs `PutObject`. This is the recommended least-privilege policy for production.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject"],
      "Resource": "arn:aws:s3:::BUCKET/PREFIX/*"
    }
  ]
}
```

### Restore Role (Read-Only)

Used for `restore` and `verify` operations.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:GetObjectVersion"
      ],
      "Resource": "arn:aws:s3:::BUCKET/PREFIX/*"
    }
  ]
}
```

`restore`/`verify` use explicit `--key` (and optional `--version-id`), so list permissions are not required by rbackup.
`HeadObject` is used by the restore/verify check before download; on AWS, it is authorized by `s3:GetObject`.

Optional convenience permission (not required by restore/verify):

```json
{
  "Effect": "Allow",
  "Action": ["s3:ListBucket"],
  "Resource": "arn:aws:s3:::BUCKET"
}
```

Add `s3:ListBucket` if this role must run `rbackup config test --read` (`HeadBucket` only) or perform manual object discovery from this role.

### Full Access (Admin / Test)

Union of backup + restore, plus `s3:ListBucket` for `config test --read` (`HeadBucket` only).

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:GetObjectVersion",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::BUCKET",
        "arn:aws:s3:::BUCKET/PREFIX/*"
      ]
    }
  ]
}
```

## S3 Versioning

Enable versioning to support `--version-id` replay and rollback safety:

```bash
aws s3api put-bucket-versioning \
  --bucket BUCKET \
  --versioning-configuration Status=Enabled
```

With versioning enabled, each `PutObject` creates a new version. Backup receipts include `version_id` for deterministic restore. Without versioning, `--version-id` is unavailable and restoring after overwrite is impossible.

## S3 Object Lock

Object Lock (compliance mode) prevents deletion or overwrite of backup objects for a retention period, protecting against ransomware or accidental deletion.

Object Lock requires versioning and must be enabled at bucket creation time. Use compliance mode (not governance) for immutable backups — compliance mode cannot be bypassed even by the root account during the retention period.

## Lifecycle Rules

Use lifecycle rules to expire old object versions after a retention period, controlling storage costs while preserving recent backups:

```json
{
  "Rules": [
    {
      "ID": "expire-old-versions",
      "Status": "Enabled",
      "NoncurrentVersionExpiration": {
        "NoncurrentDays": 90
      },
      "Filter": {
        "Prefix": "PREFIX/"
      }
    }
  ]
}
```

Apply with:

```bash
aws s3api put-bucket-lifecycle-configuration \
  --bucket BUCKET \
  --lifecycle-configuration file://lifecycle.json
```

## Bucket Policy Notes

Deny unencrypted transport:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::BUCKET",
        "arn:aws:s3:::BUCKET/*"
      ],
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}
```

Restrict source IP if the backup host has a static IP:

```json
{
  "Condition": {
    "NotIpAddress": {
      "aws:SourceIp": "203.0.113.0/24"
    }
  }
}
```
